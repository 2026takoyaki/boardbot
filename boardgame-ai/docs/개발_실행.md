# 개발 실행 — 카메라·전구 없이 돌리기

연출(조명·모달·TTS)을 조율하려면 같은 장면을 수십 번 다시 봐야 한다. 매번
카메라 앞에 앉아 좌석을 등록하고 주사위를 굴릴 수는 없으므로, 하드웨어 없이
게임을 손으로 굴리는 모드가 있다.

## 실행

터미널 두 개.

```bash
# 1) 백엔드 — 개발 모드
cd boardgame-ai
BOARDBOT_DEV=1 python3 -m uvicorn backend.server:app --port 8000

# 2) 프론트
cd boardgame-ai/frontend
npm install   # 최초 1회
npm run dev
```

→ http://localhost:3000

개발 모드에서는 **카메라도 비전 파이프라인도 뜨지 않는다.** YOLO·MediaPipe
로딩이 빠지므로 기동이 10초대에서 2초대로 줄고, 개발 입력은 어차피 이벤트를
직접 주입하므로 잃는 것이 없다.

## 화면 우하단 DEV 패널

`BOARDBOT_DEV=1`일 때만 나타난다. 페이지마다 필요한 조작이 다르다.

| 페이지 | 버튼 | 하는 일 |
|---|---|---|
| 로비 | 전원 좌석 등록 | 카메라 없이 좌석 등록을 통과한다 |
| 요트 | 랜덤 굴림 | 아무 눈이나 굴린다 |
| 요트 | 야찌 / 라지스트레이트 | 해당 칸을 고르면 `highlight` 연출 |
| 요트 | 0점 유도 | 에이스 칸을 고르면 `zero` 연출 |
| 요트 | 후반 상황 만들기 | 7칸을 채워 `lead_change` 연출을 볼 수 있게 한다 |
| 늑대인간 | 다음 페이즈 | 밤 타이머(8~15초)를 기다리지 않고 넘긴다 |

### 연출 네 가지를 다 보는 순서

1. 플레이어 3명 등록 → **전원 좌석 등록** → 요트 시작
2. **후반 상황 만들기** — 현재 차례가 2위가 되고 나머지가 앞선다
3. **랜덤 굴림** → 아무 칸이나 → `normal` (모달 없이 점수판 안에서만)
4. **야찌** → 요트 칸 → `highlight`
5. **0점 유도** → 에이스 칸 → `zero`
6. 후반 상황에서 크게 넣으면 → `lead_change`

## 프론트 고치고 나면 lint 한 번

```bash
cd boardgame-ai/frontend && npm run lint
```

**vite 빌드는 정의되지 않은 변수를 잡지 못한다.** 번들은 멀쩡히 만들어지고
화면을 열어야 `ReferenceError`로 죽는다 — 백엔드 상수 이름(`YachtPhase.GAME_END`)을
그대로 JSX에 써넣어 요트 화면이 통째로 검게 나온 적이 있다.

`no-undef` 0건이면 그 부류는 없다. `react-hooks/exhaustive-deps` 경고는 매 렌더마다
새로 만들어지는 콜백을 `useEffect` 의존성에 넣는 실수를 잡는다 — 타이머가 계속
리셋되어 모달이 안 닫히던 버그가 그것이었다.

## 모달만 따로 보기

게임을 돌리지 않고 모달 세 개만 확인하려면 백엔드도 필요 없다.

```
http://localhost:3000/?preview=moments
```

슬라이더로 지속시간을 바꿔볼 수 있다. 값을 정했으면 두 곳에 반영한다.

1. `games/yacht/fsm.py` 의 `_CUE_DURATION_MS`
2. `bulb/scenes.py` 의 해당 Cue가 그 예산 안에 들어오는지 확인

> ⚠️ 조명 Cue는 모달이 닫히기 전에 중립으로 복귀해야 한다. 늦게 복귀하면
> 그 상태로 다음 굴림이 들어와 **주사위 인식이 깨진다** (설계문서 §2.4).

## 조명은 화면으로 본다

**개발 모드에서는 조명이 화면에 그려진다.** 별도 설정이 필요 없다 —
`frontend` 드라이버가 기본이라 전구가 없어도 무슨 색을 어떤 밝기로 요청했는지
바로 보인다.

- 화면 **가장자리**가 해당 색으로 물든다 (전구가 방을 물들이는 것과 같은 방식)
- 왼쪽 아래에 **색 점과 밝기 %** 가 뜬다. 소등이면 `소등`으로 표시된다

밝기와 전환 시간까지 실제 전구와 같은 값을 받으므로, 늑대인간 밤이 충분히
어두운지 · 요트 Cue가 중립으로 잘 돌아오는지를 눈으로 판단할 수 있다.

로그로만 보고 싶으면 `LIGHT_DRIVER=mock`으로 되돌린다.

실제 전구를 붙이려면:

```bash
BOARDBOT_DEV=1 LIGHT_DRIVER=yeelight LIGHT_BULB_IP=172.20.10.5 \
  python -m uvicorn backend.server:app --port 8000
```

전구가 여러 개면 `LIGHT_BULB_IP`에 쉼표로 나열한다. 전부 같은 색·같은 밝기로
동시에 움직이며, 연출 코드는 개수를 모른다.

```bash
LIGHT_BULB_IP=172.20.10.5,172.20.10.6
```

붙이기 전에 점검한다. 전구별로 어느 것이 안 붙는지 알려준다.

```bash
python -m tools.light_check 172.20.10.5 172.20.10.6
```

밤 밝기는 `LIGHT_NIGHT_BRIGHTNESS`(기본 15) 하나로 모든 밤 페이즈가 함께
움직인다. 현장에서 이 값만 돌려가며 맞추면 된다. **전구를 늘리면 같은 값이
실제로는 더 밝다** — 2개로 늘렸다면 이 값부터 다시 맞춰야 한다.

## 안전장치

개발 입력은 전부 `BOARDBOT_DEV` 뒤에 있다.

- 플래그가 꺼져 있으면 `/dev/*`는 **404**
- WebSocket 개발 입력(`DEV_SETUP_LATE_GAME`, `DEV_NEXT_PHASE`)은 **조용히 무시**
- DEV 패널은 `/dev/config`가 false를 주므로 **아예 렌더되지 않음**

**시연에서는 절대 켜지 마세요.** 개발 모드는 비전을 띄우지 않으므로 실제 인식이
전혀 동작하지 않습니다.

## 자주 겪는 것

| 증상 | 원인 |
|---|---|
| TTS가 안 나온다 | Google TTS 결제·키 문제. `.env`의 `GOOGLE_APPLICATION_CREDENTIALS` 확인. 없어도 게임은 돈다 |
| DEV 패널이 안 보인다 | 백엔드에 `BOARDBOT_DEV=1`이 안 붙었거나, vite 프록시가 `/dev`를 못 넘긴다 |
| 좌석 등록에서 막힌다 | 플레이어를 먼저 등록해야 **전원 좌석 등록**이 동작한다 |
